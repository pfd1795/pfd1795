Fundamentals of computing

Digital logic and Boolean algebra

Digital logic represents conditions and decisions using binary values, usually 0 and 1. Boolean algebra lets us describe and simplify those relationships, while logic gates implement them physically in circuits. Understanding the connection between expressions, truth tables and hardware helps reason about how a computer processes information.

In 5 points

  • A Boolean variable can only take two values: true or false, which in digital circuits are usually represented as 1 and 0.
  • AND is true only if all its inputs are true; OR is true if at least one input is true; NOT inverts its input.
  • A truth table lists all possible input combinations and shows the result of an expression for each combination.
  • The laws of Boolean algebra, including De Morgan's laws, let us transform expressions without changing their logical result.
  • Logic gates are circuits that perform Boolean operations; combining them lets us build more complex digital circuits.

What is it?

Digital logic studies how to represent and process information using signals that are interpreted as two states. In a binary system, those states are written as 0 and 1; in logic they are usually expressed as false and true. The correspondence is useful, but it does not mean every circuit has an identical voltage to represent each value: the concrete electrical levels depend on the technology and its tolerance margins.

Boolean algebra is a mathematical system for operating on logical values. Its main operators let us combine conditions. For example, an alarm could activate if smoke is detected and the system is armed, or if an emergency button is pressed. The Boolean expression describes that rule regardless of how the circuit is built.

In hardware, electronic components organized as logic gates execute those operations. The gates receive one or more signals and produce an output. Combining many of them lets us build circuits that compare numbers, add, store data or control the flow of operations in a processor.

In a real digital circuit, 0 and 1 represent signal ranges recognized by the component, not necessarily ideal and exact electrical values. To reason about its logical function, it is usually enough to use binary values.

Propositions and connectors

A proposition is a statement that can be assigned a truth value: true or false. In an expression, propositions can be represented with letters such as A, B and C. For example, A could mean "there is smoke" and B, "the alarm is armed".

Logical connectors combine or modify those propositions. The AND operation reads "and"; OR, "or"; NOT, "not". In circuits and technical texts their English names, mathematical symbols and programming-language operators also appear. The meaning is preserved, although the notation changes.

  • AND — conjunction: A AND B is true when both propositions are true.
  • OR — inclusive disjunction: A OR B is true when at least one proposition is true, even if both are.
  • NOT — negation: NOT A inverts the value of A.
  • XOR — exclusive disjunction: A XOR B is true when the inputs are different.

The word "or" in everyday language can mean an exclusive choice: "tea or coffee" may suggest that only one is chosen. In logic, OR is usually inclusive. When we want to express that exactly one input must be true, we use XOR or state the condition explicitly.

Parentheses help indicate which part of an expression is evaluated first. If there are no parentheses, languages and mathematical conventions apply precedence rules. Since those rules may differ by context, adding parentheses when they improve readability is a safe practice.

Truth tables

A truth table lists the input combinations of an expression and computes its output. It is a simple tool to check a rule, compare two expressions or detect a combination that produces an unexpected result.

With one input there are two possible combinations. With two inputs there are four: both false, only the first true, only the second true, and both true. In general, with n binary variables, the complete table contains 2n rows.

A methodical way to build a table is to write all input combinations first, then evaluate the sub-expressions, and finally compute the final output. For an expression with parentheses, it helps to add a column for each intermediate operation. 

variables = [A, B]
for each combination of values of A and B:
    output_and = A AND B
    output_or = A OR B
    show A, B, output_and, output_or

The pseudocode describes the procedure, not a program tied to a particular language. For three variables there are eight rows; if the table grows, organizing intermediate columns helps review each step without skipping combinations.

Simplification and De Morgan's laws

Two expressions are logically equivalent if they produce the same output for all combinations of their inputs. They can be checked by comparing their columns in a truth table. Boolean laws let us prove equivalences and simplify expressions without enumerating all rows.

Some basic laws are:

  • Identity: A AND 1 = A and A OR 0 = A.
  • Domination: A AND 0 = 0 and A OR 1 = 1.
  • Idempotence: A AND A = A and A OR A = A.
  • Complement: A AND NOT A = 0 and A OR NOT A = 1.
  • Double negation: NOT (NOT A) = A.
  • Commutativity: A AND B = B AND A and A OR B = B OR A.
  • Associativity: operations of the same type can be regrouped without changing the result.

De Morgan's laws describe how a negation distributes over an operation:

  • NOT (A AND B) = (NOT A) OR (NOT B).
  • NOT (A OR B) = (NOT A) AND (NOT B).

The idea can be understood with an everyday condition. "It is not true that the door is closed and the light is off" is equivalent to "the door is not closed or the light is not off". When negating a conjunction, AND becomes OR and each term is negated. When negating a disjunction, OR becomes AND and each term is also negated.

Simplifying can reduce the number of operations needed to represent a logical function. In circuits, that can affect the number of components, consumption or propagation delay. However, the physical result depends on the technology, design constraints and synthesis tools: an algebraically shorter expression does not by itself guarantee a better circuit in every sense.

To verify a transformation, compare the truth tables of the original and proposed expressions. If the outputs match in all rows, they are equivalent.

Logic gates

A logic gate is a circuit that performs a Boolean operation. The inputs represent binary signals and the output depends on the gate's function. The basic gates AND, OR and NOT have direct equivalents in algebra; others, such as NAND, NOR and XOR, are also common in digital circuits.

NAND and NOR are called universal gates because, by combining gates of either of those two types, any Boolean function can be implemented. This is a logical property; the concrete choice of components also depends on electrical characteristics and design.

Examples in pseudocode and JavaScript

Suppose a system opens a door if the card is valid and the user is not blocked. The rule can be expressed as cardValid AND NOT userBlocked. It is important to write the condition with the same clarity in the pseudocode and in the language used. 

if cardValid AND NOT userBlocked:
    openDoor()
else:
    keepClosed()

In JavaScript, the usual logical operators are && for AND, || for OR and ! for NOT. If the variables hold Booleans, the result also expresses a Boolean condition: 

const cardValid = true;
const userBlocked = false;

const canEnter = cardValid && !userBlocked;

if (canEnter) {
  console.log('Access allowed');
}

JavaScript allows using non-Boolean values in conditions. Its operators may apply conversion rules and, in the case of && and ||, return one of the operands instead of a strict Boolean. If we want to reason as in a truth table, it is better to work with explicit Boolean variables or convert the result carefully.

To check a priority condition, for example, an alarm that activates when there is smoke and the system is armed, or when emergency is pressed, parentheses make the rule visible: 

const hasSmoke = false;
const systemArmed = true;
const emergency = true;

const activateAlarm =
  (hasSmoke && systemArmed) || emergency;

In this case, the alarm activates if the left-hand group holds or if emergency is true. Although the precedence of && over || in JavaScript already produces that grouping, the parentheses document the intent and reduce errors when modifying the expression.

Best practices

  • Name conditions by their meaning. A name like userBlocked is easier to review than a generic variable like x.
  • Use parentheses to express intent. Even when precedence is known, explicit groups make combined conditions readable.
  • Build the table before simplifying. List the inputs and expected outputs to detect which cases the expression must cover.
  • Check equivalences. When replacing an expression with another, compare their tables or evaluate each relevant combination.
  • Distinguish inclusive OR from XOR. Confirm whether the requirement allows both conditions to be true at the same time.
  • Separate logic from physical representation. The expression describes logical behavior; the concrete circuit also has electrical and timing constraints.
  • Evaluate edge cases. Test all-false inputs, all-true inputs and mixed combinations, plus those that matter for the system.

A correct Boolean condition does not by itself guarantee that a system is safe or reliable. In real applications, inputs must also be validated, states controlled, hardware failures considered and the system's behavior under unexpected signals reviewed.

Common mistakes

Mistake Why it is wrong What to do
Interpreting OR as "exactly one". Inclusive OR is also true when both inputs are true. Use XOR or state the exclusivity explicitly.
Negating only part of an expression. It can change the result for several input combinations. Apply De Morgan's laws and check with a table.
Omitting parentheses in long conditions. Precedence may not be obvious to whoever reads or maintains the code. Group the parts according to the rule they represent.
Assuming a JavaScript value is always a Boolean. Logical operators also work with other values and may return operands. Use explicit Booleans when seeking a direct equivalence with binary logic.
Checking only one input combination. An expression may work for the tested case and fail in another. Review all rows of the table or design tests covering the relevant combinations.
Assuming a shorter expression is always better in hardware. Performance and cost also depend on the technology and circuit constraints. Treat simplification as a logical transformation and measure the physical design separately.

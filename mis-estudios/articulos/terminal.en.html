Commands and terminal

Terminal and command line

The terminal is a text interface for controlling the system: moving through folders, managing files, running programs and combining them. The examples use Bash, the most common shell on Linux and macOS.

What is a terminal?

The terminal is the program that displays text; the shell is the interpreter that reads your commands and runs them. Every command has the form program options arguments. 

echo "Hello, world"        # program: echo, no options, one argument
  ls -la /home              # options -la, argument /home
  man ls                    # manual for a command (exit with "q")

Paths: . is the current folder, .. the parent, ~ your home folder and / the system root.

Navigation

pwd                 # where am I (print working directory)
  ls                  # what's here
  ls -la              # list everything, including hidden, with details
  cd projects         # enter a folder
  cd ..               # go up one level
  cd ~                # go to my home folder
  cd -                # go back to the previous folder

Tab autocompletes names and the up arrow recalls the previous command. These are the two keys that will save you the most time.

Files and folders

mkdir new-folder        # create a folder (-p also creates parents)
  touch notes.txt            # create an empty file
  cp source destination      # copy (-r for folders)
  mv file.txt docs/          # move; also used to rename
  rm file.txt                # delete (-r folders, -i asks for confirmation)
  cat file.txt               # show its contents
  less file.txt              # view it page by page (exit with "q")
  head -n 5 file.txt         # first 5 lines
  tail -f log.txt            # last lines, live, as it grows
  find . -name "*.js"        # search by name from the current folder

rm has no recycle bin. A badly written rm -rf deletes permanently. Always check the path with pwd and ls first.

Permissions

Every file has permissions for the owner, the group and others. They can be read, written and executed (r, w, x). 

ls -l script.sh
  # -rwxr-xr-- 1 ana dev 512 ... script.sh
  #  |||| ||| |||-- others: can read
  #  |||| |||-- group: read and execute
  #  ||||-- owner: read, write and execute

  chmod +x script.sh          # add execute permission
  chmod 644 config.txt        # owner rw; group and others, read only
  chown ana:dev file.txt      # change owner and group (needs privileges)
  sudo command                # run as administrator (use with care)

The code 644 is the sum of the values r=4, w=2, x=1 for the three groups. It is the usual pattern for normal files; 755 is used for programs and folders.

Processes

ps aux               # list all running processes
  top                  # interactive monitor (exit with "q")
  kill 1234            # ask process with PID 1234 to terminate
  kill -9 1234         # force it (last resort)
  command &            # launch in the background
  jobs                 # see background jobs of this terminal
  fg                   # bring back the last background job
  Ctrl+C               # interrupt the foreground process
  Ctrl+Z               # suspend it and return control

Pipes and redirection

The Unix philosophy: small programs that do one thing well and combine. The pipe | connects the output of one to the input of the next. 

# Count how many .js files are in the project
  find . -name "*.js" | wc -l

  # Find a specific process
  ps aux | grep node

  # Save the output to a file (> overwrites, >> appends)
  ls -la > listing.txt
  echo "new line" >> listing.txt

  # Discard errors by sending them to /dev/null
  command 2> /dev/null

grep filters lines by a pattern, wc counts lines or words and sort / uniq sort and remove duplicates. Chained together they make very powerful text analysis.

Web (HTML, CSS and JavaScript)

HTML

HTML (HyperText Markup Language) is the markup language that describes the structure and meaning of a web page's content. The browser reads it and builds the DOM, the tree of nodes that CSS and JavaScript work on.

What it is and how it works

HTML is not a programming language: it has no variables, conditions or loops. It is a markup language made up of elements, written with an opening tag, content and a closing tag: <p>text</p>. Some elements need no closing tag, such as <img> or <br>.

The browser reads the HTML top to bottom and builds the DOM (Document Object Model). The appearance is defined by CSS and the dynamic behaviour by JavaScript.

Golden rule: HTML describes what each thing is (a heading, a paragraph, a quote), not how it looks. How it looks is CSS's job.

Minimum document structure

<!DOCTYPE html>
  <html lang="es">
    <head>
      <meta charset="utf-8">
      <meta name="viewport" content="width=device-width, initial-scale=1">
      <title>My page</title>
    </head>
    <body>
      <h1>Hello</h1>
      <p>First paragraph.</p>
    </body>
  </html>
  • <!DOCTYPE html> switches the browser to standards mode. Don't omit it.
  • lang="es" states the language: screen readers and translators use it.
  • charset="utf-8" is essential for correct accents and special characters.
  • viewport makes the page adapt to mobile screens.
  • The <head> holds metadata; the <body>, what is visible.

Tags and semantics

Using the right tag improves accessibility, SEO and maintainability. Landmarks divide the page into recognisable zones: 

<body>
    <header>Site header</header>
    <nav>Navigation links</nav>
    <main>
      <article>
        <h2>Article title</h2>
        <p>Main content...</p>
      </article>
      <aside>Related information</aside>
    </main>
    <footer>Page footer</footer>
  </body>

For text and links:

<p>
    Text with <strong>importance</strong>, <em>emphasis</em> and
    a <a href="css.en.html">link to CSS</a>.
  </p>
  <ul>
    <li>Unordered list item</li>
  </ul>
  <blockquote cite="https://example.org">A direct quote.</blockquote>
  <pre><code>preformatted code</code></pre>

The heading hierarchy <h1> to <h6> should be coherent: usually a single <h1> per page and no skipped levels.

Forms and accessibility

Every field must have its <label> associated through for and id: clicking the label focuses the field and screen readers announce it correctly. 

<form action="/send" method="post">
    <label for="email">Email address</label>
    <input type="email" id="email" name="email" required autocomplete="email">

    <fieldset>
      <legend>Preferences</legend>
      <label>
        <input type="checkbox" name="alerts">
        Receive alerts
      </label>
    </fieldset>

    <button type="submit">Send</button>
  </form>
  • Use the right type (email, number, date, search…): the browser validates and shows adapted keyboards.
  • required forces the field to be filled; autocomplete helps autofill.
  • fieldset and legend group related fields.
  • button type="submit" submits the form; type="button" does not.

Minimum accessibility: alt text on images, sufficient contrast, keyboard navigation and an ordered heading structure.

Best practices

  • Choose the element by its meaning, not its appearance. A button is <button>, not a <div> with a click handler.
  • Indent consistently (two spaces) and write tags and attributes in lowercase.
  • Always close attribute quotes and every element that requires it.
  • Every <img> needs alt; if it is decorative, leave it empty: alt="".
  • Validate the document to detect incorrect nesting.
  • Don't use <br> or tables for layout: that's CSS's job.

Common mistakes

Mistake Why it is wrong What to do
Forgetting charset="utf-8" Accents and symbols show up as garbled characters. Add it as the first element of the <head>.
Several <h1> and skipped levels Confuses screen readers and SEO. One <h1> per page and a continuous hierarchy.
Nesting <p> inside <p> The browser closes the paragraph early and reorders the DOM. Use valid grouping elements, such as <div>.
Styles with the style="" attribute Mixes content and presentation and is hard to maintain. Define them in CSS with semantic classes.
Tables for layout Breaks semantics and mobile adaptation. Use Flexbox or Grid; reserve tables for tabular data.

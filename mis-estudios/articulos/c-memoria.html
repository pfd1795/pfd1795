C y gestión de memoria

C es un lenguaje de programación compilado que ofrece control directo sobre la representación y el ciclo de vida de los datos. Ese control permite construir software eficiente, pero también obliga a comprender punteros, límites de memoria y liberación de recursos. Conocer la diferencia entre la pila y el montón ayuda a escribir programas más seguros y a evitar errores como fugas, accesos inválidos y desbordamientos de búfer.

En 5 puntos

  • C permite trabajar cerca de la memoria, pero el programador debe respetar los tipos, los límites de los objetos y su tiempo de vida.
  • Un puntero guarda una dirección; usarlo requiere que esa dirección sea válida y que el objeto al que apunta siga existiendo.
  • La pila suele alojar datos de duración automática, mientras que la memoria dinámica se solicita en el montón y debe gestionarse explícitamente.
  • Cada asignación dinámica que tenga éxito debe tener un plan claro de liberación, y el programa debe comprobar si la asignación falló.
  • Los accesos fuera de los límites, los punteros colgantes y las cadenas sin terminador pueden causar comportamiento indefinido y vulnerabilidades.

¿Qué es?

C es un lenguaje de propósito general que se utiliza, entre otros ámbitos, en sistemas operativos, controladores, herramientas de desarrollo y programas donde importa el control de recursos. El código fuente se compila a instrucciones que puede ejecutar una plataforma. C ofrece operaciones sobre valores y también herramientas para trabajar con direcciones de memoria.

La memoria es el espacio donde un programa mantiene instrucciones y datos mientras se ejecuta. Una variable representa un objeto con un tipo y un tiempo de vida. El tipo determina qué clase de valor puede guardar y cómo se interpreta; el tiempo de vida indica durante qué parte de la ejecución existe ese objeto.

En C, el programador puede declarar objetos con duración automática, estática o asignar memoria dinámica. En la práctica, suele hablarse de pila y montón para explicar dos formas habituales de organizar la memoria, aunque esos términos describen convenciones de implementación y no sustituyen las reglas formales del lenguaje.

Un error de memoria puede ser sutil: el programa quizá compile y funcione en una prueba, pero falle con otros datos o en otra plataforma. Algunos errores producen resultados incorrectos; otros implican comportamiento indefinido, es decir, el estándar de C no establece qué debe ocurrir. Por eso no se debe confiar en que un acceso inválido siempre provoque un fallo visible.

En C, el control de memoria no significa que el programa pueda acceder con seguridad a cualquier dirección. Solo deben usarse objetos válidos, dentro de sus límites y durante su tiempo de vida.

Compilación y estructura de un programa

Un archivo fuente de C suele tener extensión .c. El proceso de construcción incluye el preprocesamiento de directivas como #include, la compilación del código y el enlazado de los objetos resultantes con las bibliotecas necesarias. Las herramientas concretas y las opciones dependen de la plataforma.

Este programa mínimo incluye la declaración de una función estándar para imprimir texto y una función main, que es el punto de entrada habitual de una aplicación: 

#include <stdio.h>

int main(void) {
    int cantidad = 3;
    printf("Cantidad: %d\n", cantidad);
    return 0;
}

En un entorno que tenga disponible un compilador compatible con GCC, un comando de ejemplo para compilarlo sería: 

cc -std=c17 -Wall -Wextra -Wpedantic programa.c -o programa

-std=c17 solicita un modo del estándar C17 en compiladores que lo admiten, y las opciones -Wall, -Wextra y -Wpedantic activan grupos de advertencias útiles. Una advertencia no siempre indica un error, pero conviene entenderla antes de ignorarla.

La función devuelve un valor entero al entorno. Por convención, 0 suele indicar que terminó correctamente. Para programas pequeños, mantener la entrada, el procesamiento y la liberación de recursos organizados facilita seguir el flujo de ejecución.

El comando de compilación es ilustrativo: el nombre del compilador, las opciones disponibles y la ejecución del programa pueden cambiar según el sistema operativo y la cadena de herramientas instalada.

Tipos y declaración de variables

Cada objeto en C tiene un tipo. Los tipos enteros, como int y size_t, representan números enteros; los tipos de punto flotante, como double, representan valores aproximados con parte fraccionaria; y los tipos derivados, como arrays y estructuras, agrupan datos. El tipo char puede representar una unidad de carácter y también se utiliza al trabajar con bytes.

Una declaración da nombre y tipo a un objeto. Si el objeto puede cambiar, se suele llamar variable. Inicializarlo al declararlo evita depender de un valor indeterminado: 

int intentos = 0;
double temperatura = 21.5;
char inicial = 'M';

Un array contiene una cantidad fija de elementos del mismo tipo, colocados consecutivamente. Los índices de C comienzan en cero. Un array de cuatro elementos tiene índices válidos de 0 a 3; acceder a 4 queda fuera de sus límites. 

int puntuaciones[4] = {12, 18, 15, 20};

for (size_t i = 0; i < 4; i++) {
    printf("%d\n", puntuaciones[i]);
}

En el ejemplo, size_t es un tipo entero sin signo usado habitualmente para tamaños e índices. Al recorrer un array, el límite del bucle debe corresponder a la cantidad real de elementos. C no comprueba automáticamente los límites de un array en tiempo de ejecución.

Punteros y direcciones de memoria

Una variable normal contiene un valor. Un puntero es un objeto cuyo valor puede ser la dirección de otro objeto, siempre que el tipo del puntero sea compatible. La declaración int *p indica que p puede apuntar a un int.

El operador & obtiene la dirección de un objeto, y el operador *, cuando se aplica a un puntero válido, permite acceder al objeto señalado. El uso de * para declarar un puntero y para desreferenciarlo está relacionado, pero su significado concreto depende del contexto. 

int temperatura = 18;
int *puntero = &temperatura;

*puntero = 19;
printf("%d\n", temperatura);

puntero guarda la dirección de temperatura. Al escribir *puntero = 19, se modifica el objeto señalado; por eso, después, temperatura vale 19. No se debe desreferenciar un puntero nulo, indeterminado o que ya no apunta a un objeto vivo.

El valor especial NULL representa un puntero que no señala un objeto. Puede usarse para indicar «ningún objeto» y comprobar si una función devolvió un puntero válido. No es una dirección que se pueda leer o escribir.

Los punteros también aparecen al pasar datos a funciones. C pasa los argumentos por valor: una función recibe una copia del argumento. Si se quiere que una función modifique un objeto del llamador, se puede pasar un puntero a ese objeto: 

void incrementar(int *valor) {
    if (valor != NULL) {
        *valor += 1;
    }
}

La función comprueba que el puntero no sea nulo antes de usarlo. Esa comprobación no puede demostrar que cualquier dirección no nula sea válida, pero sí evita el caso específico de recibir NULL.

Pila frente a montón

La pila suele asociarse a llamadas de funciones y a objetos con duración automática. Al entrar en una función, sus variables locales automáticas dejan de existir cuando termina su bloque. En cambio, la memoria dinámica se solicita durante la ejecución y conserva su duración hasta que se libera o termina el programa.

«Montón» es el nombre habitual para la región administrada por las funciones de asignación dinámica de C. El estándar del lenguaje define el comportamiento de esas funciones y la duración de los objetos, pero no obliga a una implementación a organizar físicamente la memoria con una pila o un montón de una forma específica.

Aspecto Duración automática (a menudo en la pila) Memoria dinámica (a menudo en el montón)
Cómo se obtiene Al entrar en el bloque donde se declara el objeto. Mediante funciones como malloc o calloc.
Fin de vida Al abandonar el bloque, según las reglas del lenguaje. Al llamar a free con el puntero de la asignación.
Control habitual Lo administra el flujo de bloques y funciones. El programa debe organizar la liberación.
Uso frecuente Variables locales de tamaño y duración conocidos. Datos cuyo tamaño o duración se determina durante la ejecución.
Riesgo típico Devolver o conservar la dirección de un objeto que ya dejó de existir. Olvidar liberar, liberar dos veces o usar el objeto tras liberarlo.

La tabla describe el modelo de programación habitual, no una promesa sobre la ubicación física exacta de cada objeto. Por ejemplo, los compiladores pueden optimizar el almacenamiento siempre que el comportamiento observable siga las reglas del lenguaje.

Memoria dinámica con malloc y free

La función malloc, declarada en <stdlib.h>, solicita un número de bytes y devuelve un puntero al bloque reservado. Si no puede satisfacer la solicitud, devuelve NULL. La memoria obtenida con malloc no se inicializa: su contenido no debe leerse hasta haber escrito valores válidos.

Este ejemplo reserva espacio para cinco enteros, comprueba el resultado, inicializa los elementos, los utiliza y libera el bloque. La comprobación de tamaño evita multiplicaciones que excedan el rango de size_t. 

#include <stdint.h>
#include <stdio.h>
#include <stdlib.h>

int main(void) {
    size_t cantidad = 5;

    if (cantidad > SIZE_MAX / sizeof(int)) {
        return 1;
    }

    int *valores = malloc(cantidad * sizeof *valores);
    if (valores == NULL) {
        return 1;
    }

    for (size_t i = 0; i < cantidad; i++) {
        valores[i] = (int)(i * 10);
    }

    for (size_t i = 0; i < cantidad; i++) {
        printf("%d\n", valores[i]);
    }

    free(valores);
    return 0;
}

La expresión sizeof *valores obtiene el tamaño del tipo señalado por valores. Así, si el tipo del puntero cambia, no hace falta repetir el tipo en el cálculo. La conversión de i a int es explícita; en este ejemplo el rango es pequeño y conocido.

free debe recibir un puntero devuelto por una función de asignación dinámica que aún no haya sido liberado. Liberar un objeto automático, pasar una dirección incorrecta o volver a liberar el mismo bloque tiene comportamiento indefinido. Después de liberar un bloque, los punteros que lo señalaban quedan colgantes: ya no deben usarse para acceder al objeto.

Asignar NULL a una variable puntero después de free puede ayudar a evitar que esa variable conserve un valor obsoleto: 

free(valores);
valores = NULL;

Esto solo limpia esa variable. Si existen copias del puntero, también quedan colgantes y deben dejar de usarse. Poner a cero un puntero no libera memoria por sí mismo; la liberación ocurre en la llamada válida a free.

Para reservar memoria inicializada a cero existe calloc, que recibe una cantidad de elementos y el tamaño de cada uno. Para cambiar el tamaño de un bloque existe realloc, pero debe usarse con cuidado: si falla, devuelve NULL y el bloque original continúa reservado. Guardar su resultado primero en un puntero temporal evita perder la única referencia al bloque original. 

int *temporal = realloc(valores, nueva_cantidad * sizeof *valores);

if (temporal != NULL) {
    valores = temporal;
} else {
    /* valores sigue apuntando al bloque original */
}

El ejemplo de realloc es un patrón parcial: antes de calcular el nuevo tamaño también hay que validar que la multiplicación no desborde, y el programa debe definir cómo manejar el fallo. No uses el bloque original después de que una operación de redimensionado haya tenido éxito si su dirección anterior dejó de ser válida.

Cadenas de caracteres

C no tiene un tipo de cadena incorporado equivalente a los de algunos lenguajes de alto nivel. Una cadena convencional es un array de char que termina con el carácter nulo '\0'. Ese terminador indica dónde acaba el texto; no debe confundirse con el carácter '0'.

Para almacenar el texto sol se necesitan cuatro posiciones: tres letras y el terminador. La declaración siguiente deja espacio para ese terminador: 

char palabra[] = "sol";

Al copiar o construir cadenas, hay que reservar suficiente espacio para todos los caracteres y el terminador. Las funciones de la biblioteca estándar pueden requerir que el programador garantice ese espacio; no todas reciben el tamaño del destino ni pueden comprobar sus límites automáticamente.

Una cadena que no contiene un terminador dentro de su array puede hacer que una función siga leyendo más allá del objeto. Un array demasiado pequeño puede provocar escrituras fuera de sus límites. Ambos errores pueden llevar a comportamiento indefinido, fallos o vulnerabilidades.

Para entradas de texto, una opción es leer una línea con fgets, proporcionando el tamaño del búfer: 

#include <stdio.h>

int main(void) {
    char nombre[32];

    if (fgets(nombre, sizeof nombre, stdin) != NULL) {
        printf("Texto recibido: %s", nombre);
    }

    return 0;
}

fgets lee como máximo un carácter menos que la capacidad indicada y termina el resultado con '\0' si la lectura tiene éxito. Si la línea es más larga, puede quedar texto pendiente en el flujo; un programa que necesite procesar entradas extensas debe definir cómo detectar y manejar esa situación.

Buenas prácticas

  • Inicializa los objetos antes de leerlos. No uses el contenido de una variable automática sin asignarle un valor válido.
  • Comprueba los resultados de asignación. Verifica si malloc, calloc o realloc devolvieron NULL.
  • Calcula tamaños con cuidado. Comprueba que la cantidad multiplicada por el tamaño de cada elemento no exceda el rango de size_t.
  • Documenta quién es responsable de liberar. Cada bloque dinámico necesita un propietario claro y una ruta de liberación, incluso cuando aparece un error.
  • Respeta los límites de arrays y cadenas. Usa la capacidad real del destino y deja espacio para el terminador nulo de las cadenas.
  • No conserves direcciones de objetos que dejan de existir. Una dirección no prolonga el tiempo de vida de una variable local.
  • Evita liberar dos veces o usar después de liberar. Tras liberar un objeto, trata todas las copias de su puntero como inválidas.
  • Activa advertencias del compilador y herramientas de análisis. Ayudan a detectar algunos errores, pero no sustituyen la revisión del diseño ni garantizan que el programa sea correcto.
  • Usa asignación automática cuando sea adecuada. Si el tamaño y la duración son conocidos, un array local puede ser más sencillo que la memoria dinámica, teniendo en cuenta los límites de recursos de la plataforma.

Diseña el flujo de errores antes de añadir asignaciones dinámicas. Una estructura simple de liberación evita que una salida temprana del programa deje recursos sin liberar.

Errores comunes

Error Qué puede ocurrir Cómo prevenirlo
Desreferenciar un puntero nulo o indeterminado. Acceso inválido y comportamiento indefinido. Inicializa los punteros y comprueba los resultados antes de usarlos.
Escribir más allá del final de un array. Se corrompen otros datos o el programa falla; también puede abrir una vulnerabilidad. Controla el índice y compara siempre con la cantidad real de elementos.
Olvidar liberar memoria dinámica. El programa retiene memoria que ya no necesita mientras el bloque siga reservado. Define la propiedad del bloque y asegúrate de liberar en todas las rutas apropiadas.
Usar un puntero después de free. El puntero queda colgante y ya no puede usarse para acceder al objeto. Invalida el uso de todos los alias y asigna NULL a la variable que se liberó.
Liberar dos veces el mismo bloque. Comportamiento indefinido. Centraliza la liberación y cambia el estado del propietario después de liberar.
Leer memoria devuelta por malloc antes de inicializarla. Se usa un valor indeterminado. Escribe valores válidos antes de leer el bloque o utiliza una función de asignación inicializada cuando corresponda.
Calcular el tamaño de una reserva con una multiplicación no comprobada. El tamaño puede desbordarse y reservar menos espacio del necesario. Comprueba el límite de la multiplicación antes de llamar a la función de asignación.
Devolver la dirección de una variable local automática. La variable deja de existir al salir de la función y el puntero queda inválido. Devuelve un valor por copia, usa un objeto con duración adecuada o define claramente una estrategia de propiedad dinámica.

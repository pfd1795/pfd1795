Artificial intelligence

Machine learning

Machine learning is the area of artificial intelligence that lets a system adjust a model from data, instead of programming all the rules by hand. In this article you will see what it is, what types of learning exist, how a model is trained and evaluated, and which mistakes to avoid when applying it.

In 5 points

  • Instead of writing rules manually, examples are provided and the system adjusts a model.
  • Supervised learning uses labeled examples; unsupervised learning looks for structure; reinforcement learning learns by trial and error.
  • Training and evaluation are distinct stages: evaluation needs data the model has not seen.
  • A model that memorizes the training data (overfitting) fails on new examples.
  • A model's usefulness depends on the data, the chosen metric and the context of use.

What is machine learning?

Machine learning is a set of techniques that let a system improve its behavior on a task from data, without a person specifying every rule. In classical programming, the person writes the rules and the program applies them to the data; in machine learning, examples are provided and the training process produces the model that solves the task.

It is one of the areas within artificial intelligence, and today it is the basis of applications such as spam filters, recommenders, speech recognition and generative systems. Not every AI system uses machine learning: there are rule-based or search-based methods that do not learn from data.

Key idea: in classical programming, rules are written that transform data into answers; in machine learning, data and answers are used to obtain the rules (the model).

Key concepts

  • Example or instance: a concrete case of the task, for example an image or a row in a table.
  • Feature: each measurable property of an example, such as the size of a house or a user's age.
  • Label: the expected answer for an example in supervised tasks, such as the category of an image.
  • Model: mathematical representation that transforms inputs into outputs and is adjusted during training.
  • Parameters: internal values of the model that training modifies, such as the weights of a line or a neural network.
  • Hyperparameters: values that a person configures before training, such as the number of neighbors or the learning rate.
  • Loss or cost function: measure of the error between what the model predicts and what is expected; training seeks to minimize it.
  • Optimization: process of adjusting parameters to reduce the loss, for example through gradient descent.
  • Datasets: partitions of the examples used to train, validate and evaluate the model.
  • Inference: use of the already trained model to produce outputs on new inputs.
  • Generalization: ability of the model to perform well on data that was not part of training.

Types of learning

Supervised learning

It is trained with examples that include the correct label. If the label is a category, the task is classification (for example, deciding whether an email is spam or not); if it is a numeric value, the task is regression (for example, estimating a price).

Unsupervised learning

The examples have no labels and the goal is to discover structure: grouping similar cases (clustering), reducing the number of dimensions while keeping what matters, or finding association rules between items.

Reinforcement learning

An agent takes decisions in an environment and learns from rewards or penalties, without labeled examples. It is used in sequential tasks such as process control or games.

Type What it receives What it produces Typical tasks
Supervised Examples with labels Model that predicts the label Classify images, estimate prices
Unsupervised Examples without labels Structure: groups, dimensions, associations Segment customers, compress data
Reinforcement Interactions with an environment Decision policy Games, control, robotics

How a model is trained

In a typical supervised learning flow, training consists of adjusting the model's parameters so that its predictions get closer to the examples' labels. The process usually follows these steps:

  1. Define the task: state what input the system receives, what output is expected and how success will be measured.
  2. Gather and prepare the data: select features, review errors and missing values.
  3. Split the data: set aside examples for evaluation that the model will not use during training.
  4. Train: adjust parameters minimizing the loss function on the training data.
  5. Evaluate: measure behavior with the held-out data and analyze the errors.
  6. Use and monitor: apply the model in its context and watch that it remains adequate.

Any future information that leaks into training invalidates the evaluation: this is data leakage. For example, using variables to predict a month's sales that are only known after the month closes.

Generalization and overfitting

The goal is not to be right on the training data, but to generalize to new examples. When a model fits the training examples so well that it memorizes their particularities, it suffers overfitting: its performance on new data gets worse. At the opposite extreme, a model that is too simple suffers underfitting: it does not even describe the training data well.

To detect it, compare metrics on training and evaluation: a large difference usually indicates overfitting. Common techniques to mitigate it include using more data, simplifying the model or applying regularization.

Golden rule: never evaluate a model with the same data it was trained on, and do not tune hyperparameters using the test set.

Illustrative examples

These examples use basic Python, without machine learning libraries, to show the underlying ideas. In real projects, libraries such as scikit-learn are used.

Training is adjusting parameters: a line by least squares

The simplest model with parameters is a line y = slope·x + intercept. «Training» consists of computing the two parameters that minimize the squared error against the examples. 

# Fit a line y = slope * x + intercept to the examples
# (least squares). "Training" here is computing those two numbers.
xs = [1, 2, 3, 4, 5]
ys = [2.1, 4.0, 6.2, 7.9, 10.1]

n = len(xs)
mean_x = sum(xs) / n
mean_y = sum(ys) / n

slope = sum((x - mean_x) * (y - mean_y) for x, y in zip(xs, ys))
slope /= sum((x - mean_x) ** 2 for x in xs)
intercept = mean_y - slope * mean_x

print(intercept, slope)  # ≈ 0.09 1.99

def predict(x):
    return slope * x + intercept

print(predict(6))        # ≈ 12.03

A model based on examples: nearest neighbors

In nearest neighbors (k-NN) the «model» is the stored examples themselves: to classify a new point, the k closest examples are found and their majority class is voted. 

import math

# The "model" is the known examples.
points = [
    {"x": 1, "y": 1, "class": "A"},
    {"x": 2, "y": 1, "class": "A"},
    {"x": 1, "y": 2, "class": "A"},
    {"x": 6, "y": 6, "class": "B"},
    {"x": 7, "y": 6, "class": "B"},
    {"x": 6, "y": 7, "class": "B"},
    {"x": 7, "y": 7, "class": "B"},
]

def distance(a, b):
    return math.sqrt((a["x"] - b["x"]) ** 2 + (a["y"] - b["y"]) ** 2)

def classify(point, examples, k=3):
    # Find the k closest examples and vote their majority class.
    ordered = sorted(examples, key=lambda e: distance(e, point))
    votes = [e["class"] for e in ordered[:k]]
    return max(set(votes), key=votes.count)

new = {"x": 2, "y": 2, "class": "?"}
print(classify(new, points))  # A

Evaluate with unseen data

Evaluation measures how the model behaves on held-out examples that did not take part in training. Here the «training» is the stored points. 

# Set aside examples for evaluation: the model must not have "seen" them.
training = points[:5]
evaluation = points[5:]

correct = 0
for example in evaluation:
    if classify(example, training) == example["class"]:
        correct += 1

print("Accuracy:", correct / len(evaluation))

With very few examples, the evaluation result is unreliable. In practice, hundreds or thousands of examples are used and the evaluation is repeated to obtain stable measures.

Evaluation metrics

The choice of metric depends on the task and on the cost of being wrong. For classification, accuracy, precision, recall and their combination F1 are used; for regression, errors such as the mean absolute error or the mean squared error.

Metric What it measures Caution
accuracy Proportion of correct predictions over the total. Misleading with imbalanced classes: always predicting the majority class can give a high value.
precision Of the times the model predicted a class, how many were right. Says nothing about the positive cases the model missed.
recall Of the real cases of a class, how many the model detected. Can rise at the cost of generating more false positives.
F1 Harmonic mean between precision and recall. Summarizes two aspects, but hides which of the two fails.
mean squared error Average error of a numeric prediction, penalizing larger errors more. Its units are squared; to interpret it, the mean absolute error is also useful.

To understand these values it helps to review the confusion matrix, which breaks down hits and errors by class, and to analyze concrete examples where the model fails.

Best practices

  • Start with the question: define the task, the expected outcome and the cost of errors before choosing the model.
  • Know the data before training it: review ranges, missing values and labeling errors.
  • Always separate an evaluation set and do not touch it until the final measurement.
  • Choose metrics suited to the problem and to class imbalance.
  • Compare against a simple baseline before using complex models.
  • Record versions of data, hyperparameters and results so training can be reproduced.
  • Review the model's errors and who they affect, not just the global metric.
  • Re-evaluate the model when data or the context of use change.

Common mistakes

Mistake Why it is a problem What to do
Evaluating with the training data The model may have memorized them; the measure does not reflect generalization. Set aside examples that training does not use.
Tuning hyperparameters with the test set The test set stops being an impartial measurement. Use a third validation set or cross-validation.
Relying only on accuracy with imbalanced classes A trivial model can look good without detecting the minority class. Complement with precision, recall and confusion matrix.
Always seeking the most complex model Increases overfitting risk and maintenance cost. Compare against a simple baseline and justify the extra complexity.
Letting future information enter training Evaluation gives unrealistic results that will not hold in use. Review what information is available at prediction time.
Ignoring data drift Real-world data change and the model becomes outdated. Monitor performance and retrain when needed.

Quick reference

Term Meaning
feature Measurable property of an example used as input to the model.
label Expected answer of an example in supervised learning.
parameters Internal values of the model adjusted by training.
hyperparameters Values configured before training that the model does not learn.
loss function Measure of the error that training tries to minimize.
overfitting The model memorizes training and performs worse on new data.
underfitting The model is too simple and does not even describe the training data.
test set Examples set aside to measure the model without interfering with its adjustment.

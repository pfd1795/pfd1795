Fundamentos de computación

Sistemas numéricos y representación de datos

Todo lo que hace un ordenador se reduce a bits: 0 y 1. Los sistemas numéricos y las codificaciones son la forma de dar sentido a esas secuencias: enteros, decimales, texto, imágenes. Entenderlos explica por qué 0.1 + 0.2 !== 0.3, por qué un char ocupa 1 o 4 bytes, o por qué un color se escribe #ff5733.

En 5 puntos

  • El ordenador solo entiende bits (0/1); todo lo demás son convenciones de interpretación.
  • Binario, octal y hexadecimal son la misma información en bases distintas; hex es la forma compacta del binario.
  • Los enteros con signo usan complemento a dos, que permite sumar sin casos especiales.
  • Los decimales en punto flotante (IEEE 754) son aproximaciones: no todos los decimales son representables.
  • El texto se codifica (ASCII → UTF-8/Unicode); un «carácter» puede ocupar varios bytes.

Bits, bytes y unidades

Un bit es la unidad mínima: 0 o 1. Se agrupan en bytes de 8 bits, que es la unidad direccionable de la memoria. Sobre bytes se construye todo: números, texto, instrucciones.

Unidad Bits Bytes
1 byte81
1 KiB8 1921 024
1 MiB8 388 6081 048 576
1 GiB8 589 934 5921 073 741 824

Cuidado con las unidades: en almacenamiento de disco, «GB» suele ser decimal (10⁹ bytes), mientras que la memoria usa binario (GiB = 2³⁰). La diferencia explica por qué un disco de «1 TB» muestra menos espacio disponible en el SO.

Binario, octal y hexadecimal

La base indica cuántos símbolos usa cada posición. Binario (base 2) usa 0/1; octal (base 8) usa 0–7; hexadecimal (base 16) usa 0–9 y A–F. Hexadecimal es la forma compacta del binario: cada dígito hex equivale a 4 bits. 

Decimal  Binario      Octal  Hex
0        0000         0      0
5        0101         5      5
10       1010         12     A
15       1111         17     F
16       10000        20     10
255      11111111     377    FF

Conversiones rápidas: para pasar de hex a binario, sustituye cada dígito por sus 4 bits; para pasar de binario a hex, agrupa de 4 en 4 desde la derecha. Los colores CSS (#ff5733) son tres bytes en hex: rojo, verde, azul.

Enteros con signo: complemento a dos

Con N bits se representan 2ᴺ valores. Si se usan sin signo, van de 0 a 2ᴺ−1. Con signo, la convención más usada es complemento a dos: el bit más significativo indica el signo (0 positivo, 1 negativo) y los negativos se obtienen invirtiendo los bits y sumando 1. 

// 8 bits
+5  = 00000101
-5  = 11111011   (invertir 00000101 → 11111010, +1)

// Suma 5 + (-5):
  00000101
+ 11111011
-----------
 100000000   → se descarta el carry → 00000000

Ventaja: la suma funciona igual para positivos y negativos, sin circuitos especiales. El rango de un entero con signo de N bits va de −2^(N−1) a 2^(N−1)−1 (en 32 bits: −2 147 483 648 a 2 147 483 647).

Evita el «sign-magnitude» (bit de signo + magnitud) y el «complemento a uno»: tienen dos representaciones del cero y complican la aritmética. Complemento a dos es el estándar.

Punto flotante (IEEE 754)

Para representar decimales se usa la notación científica en binario: signo, mantisa y exponente. El estándar IEEE 754 define formatos de 32 bits (float) y 64 bits (double).

  • float (32 bits): 1 bit de signo, 8 de exponente, 23 de mantisa (~7 dígitos decimales).
  • double (64 bits): 1 bit de signo, 11 de exponente, 52 de mantisa (~15-17 dígitos).
  • Valores especiales: Infinity, -Infinity, NaN.
// JavaScript usa double (64 bits) para todos los números
0.1 + 0.2;            // 0.30000000000000004
(0.1 + 0.2).toFixed(2); // "0.30"

// Para dinero, mejor usar enteros (centavos) o librerías decimales
const precio = 1999; // centavos = 19.99

No todos los decimales son representables en binario (igual que 1/3 en decimal). Por eso las comparaciones de floats deben usar tolerancia (Math.abs(a-b) < epsilon), y el dinero debe manejarse en enteros o con tipos decimales.

Codificación de texto

El texto se guarda como secuencias de bytes según una codificación. ASCII (7 bits) cubre inglés básico. Unicode asigna un número (code point) a cada carácter del mundo; UTF-8 es la codificación variable que lo representa en 1–4 bytes.

Codificación Bytes por carácter Notas
ASCII1Solo inglés básico (0–127).
Latin-1 (ISO-8859-1)1Europeo occidental; sin emoji.
UTF-81–4Estándar de la web; compatible con ASCII.
UTF-162 o 4Usado por Java/Windows; BOM opcional.
UTF-324Fijo; simple pero pesado.
 
// UTF-8: 'ñ' ocupa 2 bytes, emoji 4 bytes
const bytes = new TextEncoder().encode('café');
console.log(bytes); // Uint8Array [99, 97, 102, 195, 169]

// Longitud en caracteres vs bytes
'😀'.length;        // 2 (UTF-16 code units)
[...'😀'].length;   // 1 (code point)

Un «carácter» visible (grapheme) puede ser varios code points (emoji con modificadores, acentos combinados). Para contar caracteres de usuario, usa Intl.Segmenter.

Endianness y alineación

En memoria multi-byte, el endianness define el orden de los bytes: little-endian guarda el byte menos significativo primero (x86, ARM); big-endian, el más significativo primero (redes, algunos formatos de archivo).

  • Los protocolos de red usan big-endian («network byte order»).
  • Los formatos de archivo (PNG, JPEG) especifican su orden; hay que respetarlo.
  • La alineación: acceder a datos en direcciones múltiplo de su tamaño es más rápido y a veces obligatorio.

Al parsear binarios, define explícitamente el orden de bytes (DataView en JS tiene parámetro littleEndian). No asumas el del host.

Buenas prácticas

  • Declara el encoding en HTML: <meta charset="utf-8">.
  • Usa UTF-8 en archivos, bases de datos y APIs; evita Latin-1 salvo legado.
  • Para dinero y cantidades exactas, usa enteros o tipos decimales, no float.
  • Al serializar números a texto, fija la precisión (toFixed, formateo).
  • Al leer binarios, especifica endianness y tamaño; valida rangos.
  • No confundas longitud en caracteres con bytes al truncar o validar entrada.

Errores comunes

Error Por qué está mal Qué hacer
Comparar floats con === Errores de redondeo producen falsos negativos. Usa tolerancia o redondea a N decimales.
Usar float para dinero Pérdida de precisión acumulada en sumas. Enteros en la unidad menor (centavos) o Decimal.
Confundir bytes y caracteres Truncado a mitad de un carácter UTF-8 rompe el texto. Opera sobre code points o graphemes, no bytes.
Asumir ASCII en entrada del usuario Nombres con acentos/emoji fallan o se corrompen. Valida y almacena en UTF-8.
Olvidar el BOM o el endianness al leer archivos Los primeros bytes se interpretan como datos. Detecta/elimina BOM y especifica el orden.

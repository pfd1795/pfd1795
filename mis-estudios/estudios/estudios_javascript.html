JavaScript

JavaScript es el lenguaje de programación que añade comportamiento a las páginas web: responde a eventos, modifica el DOM y se comunica con servidores. Hoy también se usa fuera del navegador.

¿Qué es y dónde se ejecuta?

JavaScript (JS) se ejecuta en un motor (V8 en Chrome, SpiderMonkey en Firefox). Dentro del navegador tiene acceso a APIs como el DOM y los eventos; fuera, en Node.js, accede al sistema de archivos y a la red del servidor.

Se incluye en una página con la etiqueta <script>:

<!-- Al final del body: el DOM ya existe cuando se ejecuta -->
  <script src="js/app.js"></script>

El atributo defer descarga el script en paralelo y lo ejecuta cuando el HTML está analizado, sin bloquear el dibujado de la página.

Variables y tipos

Declara con const siempre que puedas y con let si el valor cambiará. Evita var por su ámbito confuso. 

const nombre = 'Ana';          // string
  let contador = 0;              // number
  const activo = true;           // boolean
  const vacio = null;            // ausencia intencional de valor
  let sinDefinir;                // undefined

  // Comparaciones: usa === (estricta), no == (convierte tipos)
  1 == '1';   // true  (evítalo)
  1 === '1';  // false (correcto)

  // Plantillas de texto con acentos graves
  console.log(`Hola, ${nombre}: ${contador + 1} mensajes`);

Los tipos primitivos son string, number, boolean, null, undefined, bigint y symbol. Todo lo demás (objetos, arrays, funciones) son referencias.

Funciones y ámbito

// Declaración clásica
  function sumar(a, b) {
    return a + b;
  }

  // Función flecha, más breve (y sin su propio this)
  const doblar = (n) => n * 2;

  // Array de objetos + métodos de array
  const tareas = [
    { texto: 'Estudiar', hecha: false },
    { texto: 'Repasar', hecha: true }
  ];

  const pendientes = tareas
    .filter((t) => !t.hecha)   // filtra
    .map((t) => t.texto);      // transforma

  console.log(pendientes); // ['Estudiar']

Una función tiene acceso a las variables de su ámbito y de los ámbitos que la contienen (closure). Cada módulo o bloque crea un ámbito con let y const.

El DOM y los eventos

El DOM es la representación en memoria del HTML. JS puede leerlo, modificarlo y reaccionar a lo que hace el usuario. 

const input = document.querySelector('#buscador');
  const lista = document.querySelector('.lista-estudios');

  // Reaccionar a la escritura del usuario
  input.addEventListener('input', (evento) => {
    const valor = evento.target.value.toLowerCase();

    lista.querySelectorAll('li').forEach((item) => {
      const coincide = item.textContent.toLowerCase().includes(valor);
      item.hidden = !coincide; // cambiar el DOM según el texto
    });
  });

Usa querySelector y addEventListener en vez de atributos onclick en el HTML: separa el comportamiento del contenido.

Asincronía

JavaScript es de un solo hilo, pero no se bloquea: las operaciones lentas (red, temporizadores) se delegan y se retoman cuando terminan. 

// async/await: escrita de forma secuencial, ejecución asíncrona
  async function obtenerUsuarios() {
    try {
      const respuesta = await fetch('/api/usuarios');
      if (!respuesta.ok) {
        throw new Error('Error HTTP ' + respuesta.status);
      }
      const datos = await respuesta.json();
      return datos;
    } catch (error) {
      console.error('No se pudieron cargar los usuarios:', error);
    }
  }

await solo puede usarse dentro de una función async o en el nivel superior de un módulo. Envuélvelo siempre en try/catch para manejar fallos.

Buenas prácticas

  • Usa const por defecto y let solo cuando cambie el valor.
  • Compara siempre con === y !==.
  • Evita variables globales: encierra el código en funciones o módulos.
  • Separa la lógica del DOM de la lógica de datos.
  • Maneja los errores explícitamente en lugar de silenciarlos.
  • Ejecuta el código tras cargar el DOM (defer o DOMContentLoaded).

Errores comunes

  • Usar == y llevarse sorpresas con las conversiones de tipo.
  • Confundir null con undefined al comprobar valores.
  • Modificar un array mientras se recorre.
  • Pensar que una función async bloquea: siempre devuelve una promesa.
  • Olvidar preventDefault() en un formulario y recargar la página sin querer.
  • Mutaciones inesperadas por compartir referencias entre objetos.

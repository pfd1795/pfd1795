Paradigmas de programación

Un paradigma es una forma de pensar y estructurar un programa: qué entidades existen (variables, funciones, objetos), cómo se controla el flujo y cómo se gestionan los datos. No es lo mismo que un lenguaje: un lenguaje puede soportar varios paradigmas. Entenderlos permite elegir la herramienta adecuada y leer código ajeno con menos fricción.

En 5 puntos

  • El paradigma imperativo describe paso a paso cómo cambiar el estado del programa.
  • La programación orientada a objetos agrupa datos y comportamiento en objetos con encapsulación, herencia y polimorfismo.
  • El paradigma funcional trata las funciones como valores, evita el estado mutable y favorece composición.
  • El paradigma declarativo describe el resultado deseado; el cómo lo decide el motor (SQL, HTML, JSX).
  • La mayoría de los lenguajes modernos son multiparadigma; se mezclan según el problema.

¿Qué es un paradigma?

Un paradigma de programación es un estilo de resolver problemas con código. Define:

  • Las abstracciones disponibles (variables, funciones, clases, procesos).
  • El flujo de control (secuencia, condicionales, recursión, eventos).
  • La gestión del estado (mutable, inmutable, compartido, aislado).
  • La composición (cómo se combinan las piezas).

Un lenguaje no es un paradigma. JavaScript soporta imperativo, OOP y funcional; SQL es declarativo; Haskell es funcional puro. Aprender paradigmas te hace mejor en cualquier lenguaje.

Paradigma imperativo

El programa es una secuencia de instrucciones que modifican el estado. Es el paradigma más cercano al hardware y el primero que se suele aprender. 

// Imperativo: calcular la suma de los pares
const numeros = [1, 2, 3, 4, 5];
let suma = 0;
for (let i = 0; i < numeros.length; i++) {
  if (numeros[i] % 2 === 0) {
    suma += numeros[i];
  }
}
console.log(suma); // 6

Fortalezas: control fino, rendimiento predecible, fácil de seguir paso a paso. Riesgos: estado mutable compartido, efectos secundarios y código difícil de testear si crece.

Programación orientada a objetos

Organiza el código en objetos: entidades que encapsulan datos (atributos) y comportamiento (métodos). Los principios clave:

  • Encapsulación: ocultar el estado interno y exponer solo lo necesario.
  • Herencia: crear nuevas clases a partir de otras (reutilización).
  • Polimorfismo: tratar objetos distintos de forma uniforme si comparten interfaz.
  • Abstracción: modelar lo esencial del dominio.
class CuentaBancaria {
  #saldo = 0; // privado
  depositar(monto) { this.#saldo += monto; }
  retirar(monto) {
    if (monto > this.#saldo) throw new Error('Saldo insuficiente');
    this.#saldo -= monto;
  }
  get saldo() { return this.#saldo; }
}

const c = new CuentaBancaria();
c.depositar(100);
c.retirar(30);
console.log(c.saldo); // 70

Fortalezas: modela bien dominios con entidades y reglas; facilita la extensión. Riesgos: jerarquías profundas, acoplamiento por herencia y estado mutable compartido. Por eso hoy se prefiere composición sobre herencia.

Paradigma funcional

Trata la computación como la evaluación de funciones matemáticas. Ideas centrales:

  • Funciones puras: mismo input → mismo output; sin efectos secundarios.
  • Inmutabilidad: no se modifican datos; se crean nuevos.
  • Funciones de orden superior: reciben o devuelven otras funciones.
  • Composición: combinar funciones pequeñas para formar otras.
// Funcional: suma de los pares
const numeros = [1, 2, 3, 4, 5];
const esPar = (n) => n % 2 === 0;
const sumar = (a, b) => a + b;
const resultado = numeros.filter(esPar).reduce(sumar, 0);
console.log(resultado); // 6

Fortalezas: fácil de testear, paralelizar y razonar; ideal para transformaciones de datos. Riesgos: rendimiento por crear muchas copias; curva de aprendizaje (recursión, mónadas).

Paradigma declarativo

Describe qué se quiere obtener, no cómo. El motor decide la ejecución. Ejemplos cotidianos:

  • SQL: SELECT nombre FROM cliente WHERE activo = true;
  • HTML: describe la estructura, no el dibujo.
  • React/JSX: describe la UI a partir del estado.
  • CSS: declara estilos, el navegador los aplica.

El código declarativo suele ser más corto y expresivo, pero depende de que el motor (base de datos, navegador) esté bien optimizado.

Comparación práctica

El mismo problema (suma de los pares de una lista) en cada estilo:

Paradigma Enfoque
ImperativoBucle, condición y acumulador mutables.
OOPObjeto Sumador con método que encapsula el estado.
Funcionalfilter + reduce con funciones puras.
DeclarativoConsulta o expresión que describe el resultado.

Cuándo elegir cada uno

  • Imperativo: scripts, automatización, código cercano al hardware, rendimiento crítico.
  • OOP: dominios con entidades claras, sistemas grandes con equipos, extensiones por plugins.
  • Funcional: transformación de datos, pipelines, concurrencia, código que debe ser fácil de testear.
  • Declarativo: consultas, UI, configuración, reglas de negocio expresables como datos.

En la práctica se mezclan: un backend en JavaScript puede usar OOP para el dominio y funcional para procesar listas; SQL para persistencia; JSX para la UI.

Buenas prácticas

  • Elige el paradigma por el problema, no por moda.
  • Mantén las funciones pequeñas y con un solo propósito.
  • Prefiere inmutabilidad cuando no cueste rendimiento.
  • Evita estado compartido mutable; si lo necesitas, sincroniza.
  • Usa composición antes que herencia profunda.
  • Escribe código que se lea como la intención, no como los pasos.

Errores comunes

Error Por qué está mal Qué hacer
Usar OOP para todo, incluso scripts simples Boilerplate innecesario y abstracciones forzadas. Empieza simple; introduce clases cuando haya estado y comportamiento real.
Mutar datos en funciones «puras» Efectos secundarios ocultos y bugs difíciles de reproducir. Devuelve copias; documenta si hay efectos.
Herencia profunda Acoplamiento frágil; cambios en la base rompen descendientes. Prefiere composición e interfaces.
Mezclar paradigmas sin criterio Código inconsistente y difícil de mantener. Define convenciones por capa (dominio OOP, datos funcional, UI declarativa).
Ignorar el coste de la inmutabilidad Copias masivas en bucles calientes degradan el rendimiento. Mide; usa mutación local cuando sea seguro y aislado.

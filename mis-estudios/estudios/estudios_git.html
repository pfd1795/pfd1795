Control de versiones

Git

Git es un sistema de control de versiones distribuido: registra la historia del proyecto, permite trabajar en paralelo con ramas y colaborar mediante repositorios remotos.

¿Qué es y cómo piensa?

Git guarda instantáneas (snapshots) del proyecto, no solo diferencias. Cada instantánea es un commit identificado por un hash y encadenado al anterior, lo que forma el historial.

Hay tres zonas que conviene distinguir:

Zona Qué contiene Cómo se pasa a la siguiente
Directorio de trabajoLos archivos tal como los editasgit add
Área de preparación (staging)Los cambios listos para confirmargit commit
RepositorioEl historial de commitsgit push al remoto

Un commit es un punto de guardado con significado. Preparar los cambios por partes permite crear commits pequeños y claros en lugar de uno gigante y mezclado.

Flujo básico

# Configuración inicial (una sola vez)
  git config --global user.name "Tu Nombre"
  git config --global user.email "tu@correo.com"

  # Empezar: crear un repositorio o clonar uno existente
  git init mi-proyecto
  git clone https://ejemplo.com/usuario/repo.git

  # Ciclo de trabajo diario
  git status                     # ¿qué ha cambiado?
  git add index.html             # preparar un archivo concreto
  git add .                      # preparar todos los cambios
  git commit -m "Añade el buscador"   # guardar la instantánea
  git log --oneline              # ver el historial resumido

Ramas

Una rama es una línea de desarrollo independiente. Sirven para trabajar en una función sin tocar la versión estable, normalmente main. 

git switch -c nueva-funcion     # crear una rama y cambiar a ella
  # ... trabajar y hacer commits ...

  git switch main                 # volver a la rama principal
  git merge nueva-funcion         # traer los cambios de la rama

  # Alternativa moderna: rebase reescribe la historia para dejarla lineal
  git switch nueva-funcion
  git rebase main

Nunca reescribas la historia de una rama compartida. Un rebase o un push --force sobre main rompe el trabajo de los demás. Reescribe solo tus ramas locales.

Si dos ramas tocan las mismas líneas aparece un conflicto: Git marca los archivos, tú eliges el contenido final, guardas y ejecutas git add y git commit para completar la fusión.

Repositorios remotos

git remote -v                   # ver los remotos configurados
  git remote add origin URL       # añadir un remoto llamado "origin"
  git push -u origin main         # subir la rama y enlazarla por defecto
  git pull                        # traer y fusionar los cambios del remoto
  git fetch                       # traer los cambios SIN fusionarlos aún

La diferencia clave: fetch es seguro porque solo actualiza tu copia del remoto; pull es fetch más merge y puede provocar conflictos de inmediato.

Deshacer cambios

# Descartar cambios de un archivo que NO has preparado
  git restore archivo.txt

  # Quitar un archivo del área de preparación (sin perder cambios)
  git restore --staged archivo.txt

  # Corregir el último commit (mensaje o archivos olvidados)
  git commit --amend

  # Revertir un commit ya publicado creando uno nuevo que lo deshace
  git revert a1b2c3d

  # Volver atrás en la historia local (¡solo si no está compartido!)
  git reset --hard a1b2c3d

Para trabajo local usa restore y reset; para historia ya compartida, revert, que no borra nada.

Buenas prácticas

  • Haz commits pequeños y atómicos: un cambio lógico por commit.
  • Escribe mensajes en imperativo y descriptivos: «Añade validación del correo».
  • Ignora archivos generados y secretos con un .gitignore; nunca subas claves.
  • Crea una rama por tarea y fusiónala mediante pull request o merge request.
  • Antes de trabajar, git pull para partir del estado más reciente.
  • Revisa git status y git diff antes de confirmar.

Referencia rápida

Comando Qué hace
git initCrea un repositorio en la carpeta actual.
git clone URLCopia un repositorio remoto.
git statusMuestra el estado de los archivos.
git addPasa cambios al área de preparación.
git commit -m "..."Registra una instantánea.
git log --onelineHistorial resumido de commits.
git diffDiferencias entre zonas de trabajo.
git switch -c ramaCrea y cambia a una rama.
git merge ramaFusiona una rama en la actual.
git pull / git pushTrae / envía cambios del remoto.
git restoreDescarta cambios en archivos.

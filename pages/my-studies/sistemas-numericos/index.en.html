Fundamentals of computing

Number systems and data representation

Everything a computer does comes down to bits: 0 and 1. Number systems and encodings are how we make sense of those sequences: integers, decimals, text, images. Understanding them explains why 0.1 + 0.2 !== 0.3, why a char takes 1 or 4 bytes, or why a color is written #ff5733.

In 5 points

  • The computer only understands bits (0/1); everything else is a convention of interpretation.
  • Binary, octal and hexadecimal are the same information in different bases; hex is the compact form of binary.
  • Signed integers use two's complement, which allows addition without special cases.
  • Decimals in floating point (IEEE 754) are approximations: not every decimal is representable.
  • Text is encoded (ASCII → UTF-8/Unicode); a "character" may occupy several bytes.

Bits, bytes and units

A bit is the smallest unit: 0 or 1. They are grouped into bytes of 8 bits, which is the addressable unit of memory. Everything is built on bytes: numbers, text, instructions.

Unit Bits Bytes
1 byte81
1 KiB8 1921 024
1 MiB8 388 6081 048 576
1 GiB8 589 934 5921 073 741 824

Watch out for units: in disk storage, "GB" is usually decimal (10⁹ bytes), while memory uses binary (GiB = 2³⁰). The difference explains why a "1 TB" disk shows less available space in the OS.

Binary, octal and hexadecimal

The base indicates how many symbols each position uses. Binary (base 2) uses 0/1; octal (base 8) uses 0–7; hexadecimal (base 16) uses 0–9 and A–F. Hexadecimal is the compact form of binary: each hex digit equals 4 bits. 

Decimal  Binary      Octal  Hex
0        0000         0      0
5        0101         5      5
10       1010         12     A
15       1111         17     F
16       10000        20     10
255      11111111     377    FF

Quick conversions: to go from hex to binary, replace each digit with its 4 bits; to go from binary to hex, group in 4s from the right. CSS colors (#ff5733) are three bytes in hex: red, green, blue.

Signed integers: two's complement

With N bits, 2ᴺ values are representable. Unsigned, they range from 0 to 2ᴺ−1. Signed, the most common convention is two's complement: the most significant bit indicates the sign (0 positive, 1 negative) and negatives are obtained by inverting the bits and adding 1. 

// 8 bits
+5  = 00000101
-5  = 11111011   (invert 00000101 → 11111010, +1)

// Sum 5 + (-5):
  00000101
+ 11111011
-----------
 100000000   → carry discarded → 00000000

Advantage: addition works the same for positives and negatives, with no special circuits. The range of a signed N-bit integer goes from −2^(N−1) to 2^(N−1)−1 (in 32 bits: −2 147 483 648 to 2 147 483 647).

Avoid "sign-magnitude" (sign bit + magnitude) and "one's complement": they have two representations of zero and complicate arithmetic. Two's complement is the standard.

Floating point (IEEE 754)

To represent decimals, scientific notation in binary is used: sign, mantissa and exponent. The IEEE 754 standard defines 32-bit (float) and 64-bit (double) formats.

  • float (32 bits): 1 sign bit, 8 exponent, 23 mantissa (~7 decimal digits).
  • double (64 bits): 1 sign bit, 11 exponent, 52 mantissa (~15-17 digits).
  • Special values: Infinity, -Infinity, NaN.
// JavaScript uses double (64 bits) for all numbers
0.1 + 0.2;            // 0.30000000000000004
(0.1 + 0.2).toFixed(2); // "0.30"

// For money, better use integers (cents) or decimal libraries
const price = 1999; // cents = 19.99

Not every decimal is representable in binary (just like 1/3 in decimal). That is why float comparisons must use tolerance (Math.abs(a-b) < epsilon), and money must be handled in integers or with decimal types.

Text encoding

Text is stored as byte sequences according to an encoding. ASCII (7 bits) covers basic English. Unicode assigns a number (code point) to every character in the world; UTF-8 is the variable-length encoding that represents it in 1–4 bytes.

Encoding Bytes per character Notes
ASCII1Basic English only (0–127).
Latin-1 (ISO-8859-1)1Western European; no emoji.
UTF-81–4Web standard; ASCII-compatible.
UTF-162 or 4Used by Java/Windows; optional BOM.
UTF-324Fixed; simple but heavy.
 
// UTF-8: 'ñ' takes 2 bytes, emoji 4 bytes
const bytes = new TextEncoder().encode('café');
console.log(bytes); // Uint8Array [99, 97, 102, 195, 169]

// Length in characters vs bytes
'😀'.length;        // 2 (UTF-16 code units)
[...'😀'].length;   // 1 (code point)

A visible "character" (grapheme) may be several code points (emoji with modifiers, combined accents). To count user characters, use Intl.Segmenter.

Endianness and alignment

In multi-byte memory, endianness defines the byte order: little-endian stores the least significant byte first (x86, ARM); big-endian stores the most significant byte first (networks, some file formats).

  • Network protocols use big-endian ("network byte order").
  • File formats (PNG, JPEG) specify their order; it must be respected.
  • Alignment: accessing data at addresses that are multiples of their size is faster and sometimes required.

When parsing binaries, explicitly define the byte order (DataView in JS has a littleEndian parameter). Do not assume the host's.

Best practices

  • Declare the encoding in HTML: <meta charset="utf-8">.
  • Use UTF-8 in files, databases and APIs; avoid Latin-1 except for legacy.
  • For money and exact amounts, use integers or decimal types, not float.
  • When serializing numbers to text, fix the precision (toFixed, formatting).
  • When reading binaries, specify endianness and size; validate ranges.
  • Do not confuse character length with bytes when truncating or validating input.

Common mistakes

Mistake Why it is wrong What to do
Comparing floats with === Rounding errors produce false negatives. Use tolerance or round to N decimals.
Using float for money Accumulated precision loss in sums. Integers in the smallest unit (cents) or Decimal.
Confusing bytes and characters Truncating in the middle of a UTF-8 character breaks the text. Operate on code points or graphemes, not bytes.
Assuming ASCII in user input Names with accents/emoji fail or get corrupted. Validate and store in UTF-8.
Forgetting the BOM or endianness when reading files The first bytes get interpreted as data. Detect/remove the BOM and specify the order.
